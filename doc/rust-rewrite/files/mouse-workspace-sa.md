## 1. `src/mouse_handler.h`

### 1.1 Purpose

Declares the mouse subsystem's public surface: the two `CGEventMask` bit-sets the daemon
installs on its event tap, the drag/drop action taxonomy, and `struct mouse_state` — the single
global that ties the main-thread event tap to the event-loop thread's drag handling. It also
carries the two `static char *[]` lookup tables used by `message.c` to print the current mouse
configuration.

### 1.2 Macros / constants

| Name | Line | Expansion | Notes for Rust |
| --- | --- | --- | --- |
| `MOUSE_EVENT_MASK_FFM` | `:4-11` | `(1<<kCGEventMouseMoved) \| (1<<kCGEventLeftMouseDown) \| (1<<kCGEventLeftMouseUp) \| (1<<kCGEventLeftMouseDragged) \| (1<<kCGEventRightMouseDown) \| (1<<kCGEventRightMouseUp) \| (1<<kCGEventRightMouseDragged) \| (1<<30)` | Unparenthesised macro body; it is only ever used as the sole argument at `src/yabai.c:307` and `src/window_manager.c:224,226`, so precedence never bites. Constituent values: `kCGEventLeftMouseDown`=1, `LeftMouseUp`=2, `RightMouseDown`=3, `RightMouseUp`=4, `MouseMoved`=5, `LeftMouseDragged`=6, `RightMouseDragged`=7, `kCGSEventDockControl`=30. Numeric value **0x400000FE**. |
| `MOUSE_EVENT_MASK` | `:13-19` | same minus `kCGEventMouseMoved` | Numeric value **0x400000DE**. |
| `MOUSE_HANDLER(name)` | `:21` | `CGEventRef name(CGEventTapProxy proxy, CGEventType type, CGEventRef event, void *context)` | code-generating macro; the only use is `src/mouse_handler.c:21`. |

Both masks are computed as `int` (`1 << 30` is the largest shift, so no UB) and then passed as
a `uint32_t` parameter (`mouse_handler_begin`, `:111`) into `CGEventTapCreate`, whose parameter
is `CGEventMask` = `uint64_t`. The widening is zero-extension.

**Rust:** `const MOUSE_EVENT_MASK: CGEventMask = 0x4000_00DE;` and
`MOUSE_EVENT_MASK_FFM = 0x4000_00FE;` — write them as the explicit `1u64 << n` fold so the
`kCGSEventDockControl` comment survives, and type them `u64` from the start so no widening step
is implied.

### 1.3 Enums

**`enum mouse_drop_action`** (`:23-32`) — plain sequential, `NONE=0, STACK, SWAP, WARP_TOP,
WARP_RIGHT, WARP_BOTTOM, WARP_LEFT`. Only ever produced by `mouse_determine_drop_action` and
consumed by the `switch` at `src/event_loop.c:1197` and `src/event_loop.c:1303`.
→ Rust: plain fieldless `enum`, no discriminant pinning needed (never crosses FFI).

**`enum mouse_mod`** (`:34-42`) — **bit flags, but used as a plain value**:
`NONE=0x01, ALT=0x02, SHIFT=0x04, CMD=0x08, CTRL=0x10, FN=0x20`.
`mouse_mod_from_cgflags` (`src/mouse_handler.c:5`) ORs several of them together, and the
comparison at `src/mouse_handler.c:36,65` is `mod == mouse_state->modifier`, i.e. **exact
equality of the whole bit-set**, not a mask test. `MOUSE_MOD_NONE` (0x01) is never produced by
`mouse_mod_from_cgflags` — the "no modifier" case yields `0`. So configuring
`mouse_modifier none` (`src/message.c:1623` region does not offer it; only alt/shift/cmd/ctrl/fn)
would never match. Preserve the equality comparison exactly.
→ Rust: `bitflags`-style newtype `MouseMod(u8)` with `PartialEq`, **not** a `contains()` test.

**`enum mouse_mode`** (`:44-51`) — `NONE=0, MOVE, RESIZE, SWAP, STACK`.
Note the type punning: `struct mouse_state::drop_action` (`:72`) is declared
`enum mouse_mode` yet holds `MOUSE_MODE_SWAP`/`MOUSE_MODE_STACK` and is compared against
`MOUSE_MODE_STACK` at `src/mouse_handler.c:119`. Keep the same type in Rust (do not "fix" it
into `mouse_drop_action`) or the message-layer strings at `src/message.c:1660-1664` diverge.

**Rust shape.** This is one global mutable struct straddling two threads with only
`volatile`/relaxed-atomic discipline. Recommended faithful translation:

```
struct MouseState {
    tap: AtomicPtr<__CFMachPort>,          // handle
    runloop_source: Cell<CFRunLoopSourceRef>,
    consume_mouse_click: Cell<bool>,       // main thread only
    drag_detected: Cell<bool>,             // main thread only
    consumed_event: Cell<CGEventRef>,      // main thread only
    action1: AtomicU8, action2: AtomicU8, drop_action: AtomicU8,
    modifier: AtomicU8,                    // was `volatile uint8_t`
    current_action: ..., down_location: ..., last_moved_time: ...,
    window: *mut Window, window_frame: CGRect, ffm_window_id: u32,
    direction: u8, feedback_node: *mut WindowNode,
}
```
and a `static G_MOUSE_STATE: MouseState` reached through `unsafe` accessors, mirroring
`g_mouse_state`. Do **not** wrap it in a `Mutex` in phase 2: the C never locks, and taking a
lock inside the `CGEventTap` callback would change latency/ordering semantics.
`Cell`/`UnsafeCell` + `unsafe impl Sync` documents the existing discipline honestly; phase 3
can split the main-thread-only half (`consume_mouse_click`, `drag_detected`, `consumed_event`,
`tap`, `runloop_source`) from the event-loop-only half.

### 1.5 Static tables

```
static char *mouse_mod_str[]  (:83-91)   // sparse, designated: [0x01]="none" [0x02]="alt"
                                         // [0x04]="shift" [0x08]="cmd" [0x10]="ctrl" [0x20]="fn"

```

`mouse_mod_str` is **33 entries** with 27 NULL holes, indexed by the *flag value*
(`src/message.c:1621` does `mouse_mod_str[g_mouse_state.modifier]`). If the user ever sets a
combined modifier this indexes a NULL and `fprintf("%s")` prints `(null)` — not reachable
through the current message grammar, but the array shape must be preserved because the index
is the flag value.
→ Rust: `const MOUSE_MOD_STR: [&str; 33]` with `""` in the holes, or a `match` on the flag
value returning `Option<&str>`. Prefer the array so out-of-range behaviour stays
index-shaped; the phase-2 translator must decide what a hole prints and keep `(null)`
equivalence if `message.c` can reach it.

Because the daemon is a unity build, these `static` arrays exist exactly once. In Rust they
become module `const`s in the `mouse_handler` module and are `pub(crate)` for `message`.

## 2. `src/mouse_handler.c`

### 2.1 Purpose

Holds the `CGEventTap` callback that turns raw HID mouse events into `event_loop` posts (and
swallows the modifier-click so the application underneath never sees it), plus the six
drag-and-drop mutation routines the event-loop thread runs when a managed window is dropped.
It also owns the tap's lifecycle (`begin`/`end`).

### 2.2 Globals / statics

None defined here. Three `extern` declarations at `:1-3` (`g_event_loop`, `__pending_gesture`,
`__last_gesture_time`) — see §0.2.

### 2.3 Functions

---

**`static inline uint8_t mouse_mod_from_cgflags(uint32_t cgflags)`** — `:5-16`

Folds `CGEventFlags` into the `enum mouse_mod` bit-set. Runs on the **main thread** (only caller
is `mouse_handler`, `:33,64`). Allocates nothing. External symbols: none (the
`kCGEventFlagMask*` are constants).

*Width trap:* the parameter is `uint32_t` but `CGEventGetFlags` returns `CGEventFlags` =
`uint64_t`. `kCGEventFlagMaskSecondaryFn` = `0x00800000` and all five masks tested are below
2^24, so the implicit truncation at the call site (`:33`, `:64`) is currently lossless. A Rust
translation that takes `u64` and drops the truncation is *more* correct but is a behaviour
change if Apple ever puts a tested bit above bit 31 — take `u64`, and note it.

Each test is `(cgflags & M) == M`, not `!= 0`. For single-bit masks these agree; keep the
`== M` form because `kCGEventFlagMaskAlternate` etc. are single-bit today but the source states
the stricter predicate.

→ Rust: `fn mouse_mod_from_cgflags(flags: CGEventFlags) -> u8`, pure, safe.

---

**`static MOUSE_HANDLER(mouse_handler)`** — `:21-87`
i.e. `CGEventRef mouse_handler(CGEventTapProxy proxy, CGEventType type, CGEventRef event, void *context)`

The event tap callback. **Runs on the main run loop thread** — determined from
`CFRunLoopAddSource(CFRunLoopGetMain(), ...)` at `:288`; the tap's mach port source is attached
to the main run loop, so the callback is invoked by `CFRunLoopRun` on the main thread only.

Behaviour per `type`:

- `kCGEventTapDisabledByTimeout` / `kCGEventTapDisabledByUserInput` (`:26-30`):
  relaxed-atomic load of `mouse_state->handle`, and if non-NULL `CGEventTapEnable(handle, true)`.
  These two type values are `0xFFFFFFFE`/`0xFFFFFFFF` and are *not* representable in the event
  mask — the OS delivers them regardless.
- `kCGEventLeftMouseDown` / `kCGEventRightMouseDown` (`:31-41`): `CFRetain(event)` and post
  `MOUSE_DOWN` with the retained ref as context and `mod` as `param1`. If `mod` equals the
  configured `modifier`, it *additionally* `CFRetain`s the event into `consumed_event`, sets
  `consume_mouse_click`, and **returns NULL**, swallowing the click.
- `kCGEventLeftMouseUp` / `kCGEventRightMouseUp` (`:42-57`): `CFRetain(event)` + post `MOUSE_UP`.
  If a click is being consumed and no drag happened, replays `consumed_event` then `event`
  through `CGEventTapPostEvent(proxy, ...)`, then clears the flags, `CFRelease`s
  `consumed_event` and returns NULL.
- `kCGEventLeftMouseDragged` / `kCGEventRightMouseDragged` (`:58-62`): sets `drag_detected`,
  `CFRetain` + post `MOUSE_DRAGGED`.
- `kCGEventMouseMoved` (`:63-68`): if `mod == modifier`, returns the event untouched **without
  posting** (this is the "modifier held → suppress focus-follows-mouse" path). Otherwise
  `CFRetain` + post `MOUSE_MOVED` with `mod`.
- `30` (`kCGSEventDockControl`, `:69-83`): decodes a dock-swipe gesture out of integer value
  fields and toggles `__pending_gesture` / stamps `__last_gesture_time`. Note the local `int
  type` at `:70` **shadows** the `CGEventType type` parameter.

Default: returns `event` (`:86`).

*Allocation / ownership:* each `CFRetain(event)` hands one reference to the event loop; the
matching `CFRelease` is in the event handlers — `src/event_loop.c:1151` (`MOUSE_DOWN`),
`:1232` (`MOUSE_UP`), `:1244` and the `MOUSE_DRAGGED` tail, and the `MOUSE_MOVED` handler. The
`consumed_event` retain is balanced inside this function at `:54`.
**Leak path to preserve or fix consciously:** if a `MouseDown` is consumed
(`consume_mouse_click = true`) and the tap is torn down before the matching `MouseUp`, the
`consumed_event` reference leaks. `mouse_handler_end` does not release it.

*External symbols:* `CGEventTapEnable`, `CGEventGetFlags`, `CGEventTapPostEvent`,
`CGEventGetIntegerValueField`, `CFRetain`, `CFRelease`, plus `event_loop_post` and
`read_os_timer` (yabai).

*Pragmas:* `:18-20` disable `-Wswitch` (the `case 30` is not an enumerator and most enumerators
are unhandled) and `-Wdeprecated-declarations`; `:88` pops. Rust has no analogue and needs none.

→ **Rust:** an `unsafe extern "C" fn mouse_handler(proxy: CGEventTapProxy, ty: CGEventType,
event: CGEventRef, context: *mut c_void) -> CGEventRef`. The `context` pointer is
`&G_MOUSE_STATE`, installed at `:278` and valid for the whole process, so
`&*(context as *const MouseState)` is sound. Returning NULL must be `std::ptr::null_mut()`, and
the function must **not** unwind — wrap the body in `catch_unwind` or keep it panic-free
(indexing, `unwrap`) because unwinding across the C callback boundary is UB.

**`void mouse_window_info_populate(struct mouse_state *ms, struct mouse_window_info *info)`** — `:90-106`

Computes the delta between the live window frame and the frame captured at mouse-down, and the
four "changed" booleans. **Event-loop thread** (callers `src/event_loop.c:1176,1282`).
Allocates nothing. No external symbols.

*Float trap:* `frame.origin.x` etc. are `CGFloat` = `double` on both targets; the results are
stored into `float` fields, so each subtraction is done in `double` and then **narrowed**. The
`!= 0.0f` tests at `:99-102` then run on the narrowed `float`. A Rust version that keeps `f64`
throughout would report `changed_x == true` for sub-float-epsilon deltas that C rounds to
`0.0f`. Translate as: compute in `f64`, `as f32`, then compare `!= 0.0f32`.

→ Rust: prefer `fn mouse_window_info(ms: &MouseState) -> MouseWindowInfo` returning by value;
the out-param exists only because C has no cheap aggregate return. That is not a behaviour
change and removes an uninitialised-struct read path (`src/event_loop.c:1175` declares
`struct mouse_window_info info;` uninitialised).

**`enum mouse_drop_action mouse_determine_drop_action(struct mouse_state *ms, struct window_node *src_node, struct window *dst_window, CGPoint point)`** — `:108-131`

Classifies the cursor position inside the destination window's frame into centre (stack/swap)
or one of four triangles (warp). **Event-loop thread** (`src/event_loop.c:1196,1302`).
Allocates nothing. External symbols: `CGRectContainsPoint`; yabai `triangle_contains_point`.

Geometry, verbatim in structure:
- `wp` = point relative to `dst_window->frame.origin`.
- `c` = centre rect, `origin (0.25w, 0.25h)`, `size (0.50w, 0.50h)`.
- `t`/`r`/`b`/`l` = three-point triangles in frame-local coordinates, each sharing the centre
  point `(0.5w, 0.5h)`. Order matters: `triangle_contains_point` (`helpers.h:564`) uses a signed
  cross-product sign test with **strict** inequalities, so the shared edges and the centre point
  itself return false for all four triangles. Keep the vertex order per triangle exactly.
- The centre branch additionally requires `src_node->window_count == 1` (`:118`) — a stacked
  source node can only warp, never stack/swap.

*Float trap:* `f.size.width` is `CGFloat`/`double`; `0.25f * f.size.width` promotes the literal
to `double`, so the arithmetic is `double`, but the results are stored into `CGPoint`/`CGRect`
(`double` fields) — no narrowing here. `triangle_contains_point` however computes in `float`
(`helpers.h:566-568`), narrowing each `CGPoint` component. Preserve: build the triangle vertices
in `f64` (`CGPoint`) but do the cross products in `f32`.

→ Rust: pure function returning `MouseDropAction`; `CGRectContainsPoint` can stay an FFI call
or be inlined — note `CGRectContainsPoint` is **half-open** (excludes the max edge) while
yabai's own `cgrect_contains_point` (`helpers.h:558`) is closed. Do not swap them.

**`void mouse_drop_action_stack(struct window_manager *wm, struct view *src_view, struct window *src_window, struct view *dst_view, struct window *dst_window)`** — `:133-151`

Untiles the dragged window from its source view and pushes it onto the destination node's
window stack, re-parents it in the managed-window table, drops it to `LAYER_BELOW`, orders it
directly above the node's previous top window, and animates it into the node (or the node's
zoom area). **Event-loop thread** (`src/event_loop.c:1199`).

Allocates: nothing directly. `window_manager_animate_window` takes a `struct window_capture`
by value.

External symbols: none outside yabai. Internal: `space_manager_untile_window`,
`window_manager_remove_managed_window`, `view_find_window_node`, `view_stack_window_node`,
`window_manager_add_managed_window`, `window_manager_adjust_layer`,
`scripting_addition_order_window` (→ §6), `window_manager_animate_window`.

`event_loop_post` passes the raw pointer as the event context.

**`static bool scripting_addition_request_handshake(char *version, uint32_t *attrib)`** — `:239-268`

Opens the socket, sends the 3-byte handshake frame `{0x01, 0x00, SA_OPCODE_HANDSHAKE}`, reads up
to `BUFSIZ-1` bytes, finds the first NUL, copies `[start, NUL]` inclusive into `version`, and
copies the 4 bytes after the NUL into `*attrib`.
Threads: root `--load-sa` process. Allocates nothing (two stack buffers: `char rsp[BUFSIZ]`
zero-initialised, `char bytes[4096]` partially initialised — the designated-ish initializer
`{ 0x01, 0x00, SA_OPCODE_HANDSHAKE }` zero-fills the remaining 4093 bytes).
External: `send`, `recv`, `memcpy`; yabai `socket_open`/`socket_connect`/`socket_close`.

**Pattern: `goto out` jumping *into* the `if (socket_open(...))` block's tail** (`:250` → `:263`)
so that `socket_close` still runs. This is legal C but an odd shape; in Rust it becomes an RAII
socket or an explicit `let result = (|| {...})(); close(fd); result`.

*Buffer-size relationship:* `version` is the caller's `char version[SA_SOCKET_BUFF_LEN]`
(4096, `:273`) while `rsp` is `BUFSIZ` (1024 on macOS). Since `rsp` is zero-initialised and
`recv` reads at most `sizeof(rsp)-1`, the NUL scan always terminates inside `rsp` and the
`memcpy` is bounded. Preserve the zero-initialisation or the scan becomes unbounded.

*Unchecked:* `memcpy(attrib, zero+1, 4)` may read up to 4 bytes past what was actually received —
they are zeros from the initialiser, so `attrib` is 0, which then fails the
`OSAX_ATTRIB_ALL` test. Keep the zeroing.

→ Rust: `let mut rsp = [0u8; 1024];` then
`let nul = rsp.iter().position(|&b| b == 0).unwrap();` (always Some because the array is zeroed
and the last byte is never written), `version = &rsp[..nul]`,
`attrib = u32::from_ne_bytes(rsp[nul+1..nul+5].try_into().unwrap())`. Note **native endianness**
(`memcpy`), not `from_le_bytes` — same on both targets, but say so.

**`static bool scripting_addition_send_bytes(char *bytes, int length)`** — `:422-440`
Opens a Unix socket, connects to `g_sa_socket_file`, `send`s `length` bytes, then does a
**blocking one-byte `recv`** as an ack (return value ignored), closes, and returns true iff the
`send` did not return -1.
Threads: **event-loop thread** for most callers; **window-animation pthreads** for
`swap_window_proxy_in/out`; potentially the main thread. Concurrent calls each open their own
socket, so there is no shared state beyond `g_sa_socket_file`.
External: `send`, `recv`; yabai `socket_open`/`socket_connect`/`socket_close`.

*Traps:*
- **Partial writes are not handled.** `send` returning a short count is treated as success.
  Frames are ≤ 4096 bytes and the socket is a fresh `SOCK_STREAM` with an empty buffer, so in
  practice it is atomic. Preserve (do **not** use `write_all` silently — or do, and say so).
- The ack `recv` blocks until the payload closes the connection (`src/osax/payload.m:1054-1055`,
  `shutdown` + `close`), i.e. **the caller blocks until the Dock has processed the command**.
  This is the de-facto synchronisation for every `scripting_addition_*` call. Any Rust rewrite
  that makes this async changes yabai's ordering semantics fundamentally.
- `SIGPIPE` is ignored process-wide (`src/yabai.c:152`), so a dead payload yields `EPIPE` rather
  than a signal. A Rust daemon must keep `signal(SIGPIPE, SIG_IGN)`.

→ Rust: `UnixStream::connect(&*G_SA_SOCKET_FILE)`, `stream.write(bytes)`, `stream.read(&mut [0u8;1])`,
drop. `socket_close` does `shutdown(SHUT_RDWR)` before `close`; `UnixStream`'s `Drop` only
closes. Call `stream.shutdown(Shutdown::Both)` explicitly to match.

**The eighteen command wrappers** — `:442-621`

All share the shape `sa_payload_init(); pack(...)...; return sa_payload_send(OPCODE);` and all
run on the caller's thread. None allocate. Exhaustive wire format in §8.

Two need extra notes:

- **`scripting_addition_order_window_in(uint32_t *window_list, int window_count)`** — `:586-602`
  Calls `SLSWindowIsOrderedIn(g_connection, window_list[i], &ordered_in)` per window and packs a
  zero placeholder for windows that are already ordered in. `uint8_t ordered_in = 0;` is declared
  **once outside the loop and never reset** (`:589`), so if `SLSWindowIsOrderedIn` fails for
  window *i* the previous window's answer is reused. Preserve or fix consciously.
  External: `SLSWindowIsOrderedIn` (`src/misc/extern.h:34`).

- **`scripting_addition_swap_window_proxy_in/out`** — `:544-574`
  Read `animation_list[i].skip` with `__atomic_load_n(..., __ATOMIC_RELAXED)` because the
  animation thread may flip it concurrently. When `skip` is set, they pack **only** the 4-byte
  placeholder and **omit** the proxy id — the payload side mirrors this by `continue`-ing on a
  zero wid without unpacking the proxy (`src/osax/payload.m:822,844`). This asymmetric encoding
  is load-bearing; a Rust version that always writes 8 bytes per entry desynchronises the parser
  for every subsequent entry.

## 8. Appendix A — the daemon ↔ osax wire protocol, exhaustively

### 8.1 Transport

- `AF_UNIX` / `SOCK_STREAM`, path `/tmp/yabai-sa_<user>.socket`, mode `0600`
  (`src/osax/payload.m:1086`).
- The payload binds/listens in its `__attribute__((constructor)) load_payload`
  (`src/osax/payload.m:1102-1121`) using `getenv("USER")` **inside Dock.app**, so the socket is
  named after the Dock's user. The daemon composes the same name from its own `$USER`
  (`src/yabai.c:135`) or from `$SUDO_UID` → `pw_name` (`src/sa.m:158`).
- The payload's accept loop (`handle_connection`, `src/osax/payload.m:1043-1059`) is
  **one request per connection**: accept → read one frame → dispatch → `shutdown` + `close`.
  The daemon therefore opens a fresh socket for every single command (`src/sa.m:428`).
- The daemon's blocking 1-byte `recv` (`src/sa.m:431`) returns 0 when the payload closes, which
  is what makes every SA call synchronous with respect to the Dock.

### 8.2 Framing

```
+--------+--------+--------+----------------------------+
| len_lo | len_hi | opcode |        arguments           |
+--------+--------+--------+----------------------------+
 \-- int16_t, native --/    \---- len-1 bytes ------/
```

- `len` is `int16_t` in **native byte order**, and equals `1 + sizeof(arguments)` — it counts the
  opcode byte but **not** the 2 length bytes (`src/sa.m:420`:
  `*(int16_t*)bytes = length - sizeof(length)` where `length` started at 3).
- Total bytes sent = `2 + len`.
- Payload-side validation (`read_message`, `src/osax/payload.m:1021-1041`): reads 2 bytes into
  an `int` (!), rejects `>= SA_SOCKET_BUFF_LEN` (4096) and `<= 0`, then loops reading exactly
  `len` bytes.
  *Note:* `read(sockfd, &bytes_to_read, sizeof(int16_t))` writes only the low 2 bytes of a
  4-byte `int` that was initialised to 0, so the high half stays zero — little-endian dependent
  and fine on both targets.
- Arguments are packed with `memcpy` at whatever offset the running total reaches: **unaligned,
  no padding, native byte order** (`src/sa.m:419` / `src/osax/payload.m:41`).

### 8.4 The handshake response (`do_handshake`, `src/osax/payload.m:932-955`)

```
"2.1.30" '\0' <u32 attrib, native> '\n'
 \--6--/  \1/  \------- 4 -------/  \1/      = 12 bytes, sent in one send()
```

The daemon parses it at `src/sa.m:252-257`: scan to the first NUL, copy `[0..=nul]` into
`version`, then read the next 4 bytes as `attrib`. The trailing `'\n'` is ignored.

**`attrib` bit meaning** (`src/osax/payload.m:936-942`) — each bit says the payload successfully
located one piece of Dock.app internals. `scripting_addition_perform_validation`
(`src/sa.m:282`) requires all seven (`0x7F`) and otherwise reports
`"payload (0x%X) doesn't support this macOS version!"`.

## 9. Appendix B — install & load pipeline, and what `build.rs` must do

### 9.1 What lands on disk (`scripting_addition_install`, `src/sa.m:202`)

```
/Library/ScriptingAdditions/yabai.osax/                       0755
    Contents/                                                 0755
        Info.plist                              <- sa_plist        (src/sa.m:21)
        MacOS/                                                0755
            loader                              <- __src_osax_loader   (chmod +x, codesign -f -s -)
        Resources/                                            0755
            payload.bundle/                                   0755
                Contents/                                     0755
                    Info.plist                  <- sa_bundle_plist (src/sa.m:50)
                    MacOS/                                    0755
                        payload                 <- __src_osax_payload  (chmod +x, codesign -f -s -)
```

`umask(S_IWGRP | S_IWOTH)` at `:204` is what turns `mkdir(0755)`/`fopen` defaults into
group/other-unwritable.

### 9.2 Injection (`mach_loader_inject_payload`, `src/sa.m:333` → `src/osax/loader.m`)

The `loader` executable (arm64e/x86_64 universal) is `popen`'d. It:
1. finds Dock.app's pid via `NSRunningApplication` + `isFinishedLaunching` (`loader.m:107`);
2. `task_for_pid` (requires SIP's debugging restrictions disabled);
3. allocates a 16 KiB stack and a code page in the Dock's task;
4. patches `pthread_create_from_mach_thread`, `dlopen` and the hard-coded `payload_path`
   (`loader.m:13`) into the shellcode (`loader.m:162-176`);
5. creates a remote thread (`thread_create_running` on x86_64; on arm64e
   `thread_create` + `thread_convert_thread_state` + either `thread_create_running` on
   macOS ≥ 14.4 or `thread_set_state` + `thread_resume`) (`loader.m:188-254`);
6. polls `rax`/`x[0]` for the sentinel `0x79616265` (`"yaba"` little-endian) up to 10 times with
   20 ms sleeps, then terminates the thread and exits 0/1 (`loader.m:256-284`).

The shellcode `dlopen`s the payload bundle's `payload` binary; its
`__attribute__((constructor)) load_payload` (`src/osax/payload.m:1102`) then binds the socket.

**None of this moves to Rust.** `loader.m`, `payload.m`, `arm64_payload.m`, `x64_payload.m` and
`common.h` stay as-is and are compiled by `build.rs` with `xcrun clang` exactly as `makefile:31-32`
does.

### 9.3 `build.rs` checklist for phase 2

1. `xcrun clang src/osax/payload.m -shared -fPIC -O3 -mmacosx-version-min=11.0 -arch x86_64 -arch arm64e -o $OUT_DIR/payload -F/System/Library/PrivateFrameworks -framework SkyLight -framework Foundation -framework Carbon`
2. `xcrun clang src/osax/loader.m -O3 -mmacosx-version-min=11.0 -arch x86_64 -arch arm64e -o $OUT_DIR/loader -framework Cocoa`
3. `println!("cargo:rerun-if-changed=src/osax/payload.m")` (and `loader.m`, `arm64_payload.m`,
   `x64_payload.m`, `common.h`, `src/misc/hashtable.h` — `payload.m:37` includes it).
4. Rust side: `const OSAX_PAYLOAD: &[u8] = include_bytes!(concat!(env!("OUT_DIR"), "/payload"));`
   and the same for `loader`, replacing `__src_osax_payload{,_len}` / `__src_osax_loader{,_len}`.
5. The yabai binary itself still needs `-sectcreate __TEXT __info_plist assets/Info.plist`
   (`makefile:4`) — pass it through
   `println!("cargo:rustc-link-arg=-Wl,-sectcreate,__TEXT,__info_plist,assets/Info.plist")`.
6. Frameworks for the main binary (`makefile:2`): `Carbon`, `Cocoa`, `CoreServices`,
   `CoreVideo`, `SkyLight` (the last needs `-F/System/Library/PrivateFrameworks`).
