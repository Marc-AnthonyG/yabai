# State-access closure

`state-access.tsv` is generated by `state-access-closure.py` from the C sources (everything
under `src/` except `src/osax/` and `manifest.m`). One row per C function:

| column | meaning |
| --- | --- |
| `function` | C name; event handlers appear as `EVENT_HANDLER_<TYPE>`, Objective-C methods as `objc_method_<selector parts>` |
| `file`, `line` | where the definition starts |
| `explicit_manager_parameters` | managers the C signature already takes by pointer |
| `direct_globals` | `g_*` names referenced in the body |
| `transitive_globals` | `direct_globals` plus those of every callee, to a fixed point |
| `called_from_other_files` | files other than its own that call it, so its Rust visibility is `pub(crate)` |

Decision 13 reads a function's Rust manager parameters from this table: the C parameters, then
one `&mut` parameter for each event-loop-owned global in `transitive_globals` that no C
parameter already covers.

Regenerate with `python3 doc/rust-rewrite/state-access-closure.py . doc/rust-rewrite/state-access.tsv`.
The extraction is textual: a callee reached only through a function pointer or a macro that
hides the call is not followed.
